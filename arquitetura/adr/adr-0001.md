# ADR-001: Adoção do TimescaleDB para armazenamento de séries temporais

## Status

Aceito

## Context

O projeto consiste no desenvolvimento de uma solução de manutenção preventiva de maquinário industrial baseada em Internet of Things (IoT).

O sistema deverá receber continuamente dados provenientes de sensores instalados nas máquinas industriais, como temperatura, vibração, pressão e outras variáveis operacionais relevantes.

Essas informações serão utilizadas para monitorar as condições de funcionamento dos equipamentos, identificar comportamentos anormais e fornecer subsídios para funcionalidades de análise de limiares críticos e abertura automática de ordens de serviço.

Devido à natureza dos dados coletados, o sistema apresenta características específicas:

- Alto volume de inserções contínuas de registros.
- Necessidade de associar cada leitura a uma marcação temporal (timestamp).
- Consultas históricas por máquina, sensor e intervalo de tempo.
- Necessidade de realizar agregações e análises sobre períodos específicos.
- Crescimento contínuo do volume de dados armazenados.
- Necessidade de integração com ferramentas de visualização e monitoramento.

O stack tecnológico definido para o projeto inclui Apache Kafka, EMQX, TimescaleDB e Grafana.

Nesse contexto, torna-se necessário selecionar uma solução de persistência capaz de armazenar e consultar eficientemente dados temporais, mantendo compatibilidade com o ecossistema PostgreSQL.

## Decision

Será adotado o **TimescaleDB** como solução de armazenamento das leituras provenientes dos sensores industriais.

O TimescaleDB é uma extensão do PostgreSQL especializada no gerenciamento de séries temporais, oferecendo recursos específicos para trabalhar com grandes volumes de dados organizados cronologicamente.

A escolha considera os seguintes recursos:

### 1. Hypertables

As leituras dos sensores serão armazenadas em tabelas temporais chamadas hypertables, permitindo particionamento automático dos dados com base no tempo.

Essa abordagem facilita o gerenciamento de grandes volumes de registros e melhora a eficiência de determinadas consultas temporais.

### 2. Compatibilidade com PostgreSQL

A solução mantém a compatibilidade com o ecossistema PostgreSQL, permitindo utilizar SQL para inserção, consulta e manipulação dos dados.

Isso também facilita a integração com ferramentas externas e bibliotecas que já oferecem suporte ao PostgreSQL.

### 3. Consultas temporais

O banco será utilizado para realizar consultas históricas das leituras, considerando intervalos de tempo, identificação das máquinas e sensores associados.

### 4. Agregações e análises

Os recursos de agregação temporal permitirão calcular médias, máximos, mínimos e outras métricas operacionais em intervalos específicos.

Essas informações poderão ser utilizadas futuramente para identificar tendências e comportamentos anormais nas máquinas.

### 5. Integração com Grafana

O TimescaleDB será utilizado como fonte de dados para o Grafana, permitindo a construção de dashboards para visualização das leituras e acompanhamento das condições operacionais dos equipamentos.

### Modelo lógico de armazenamento

Será adotada uma estrutura inicial de dados contendo:

| Campo | Tipo sugerido | Descrição |
|---|---|---|
| time | TIMESTAMPTZ | Data e hora da leitura. |
| machine_id | UUID | Identificador da máquina. |
| sensor_id | UUID | Identificador do sensor. |
| variable | VARCHAR | Variável monitorada. |
| value | DOUBLE PRECISION | Valor numérico capturado. |

A tabela de leituras será implementada como uma hypertable, utilizando o campo `time` como dimensão temporal.

Exemplo conceitual de estrutura:

```sql
CREATE TABLE sensor_readings (
    time TIMESTAMPTZ NOT NULL,
    machine_id UUID NOT NULL,
    sensor_id UUID NOT NULL,
    variable VARCHAR(100) NOT NULL,
    value DOUBLE PRECISION NOT NULL
);

SELECT create_hypertable(
    'sensor_readings',
    by_range('time')
);
```

O fluxo de persistência será realizado por um consumidor do Apache Kafka, responsável por receber os eventos publicados na plataforma de streaming, validar os dados e inseri-los no TimescaleDB.

## Consequences

### Consequências positivas

- **Otimização para séries temporais:** o TimescaleDB oferece recursos especializados para armazenamento e consulta de dados organizados cronologicamente.
- **Compatibilidade com PostgreSQL:** permite utilizar SQL e aproveitar ferramentas, bibliotecas e conhecimentos já consolidados no ecossistema PostgreSQL.
- **Escalabilidade de armazenamento:** o particionamento por hypertables facilita o gerenciamento de grandes volumes de dados temporais.
- **Consultas históricas:** permite consultar o comportamento de máquinas e sensores em períodos específicos.
- **Agregações temporais:** possibilita calcular métricas operacionais, como médias, máximos e mínimos por intervalo de tempo.
- **Integração com Grafana:** permite utilizar os dados armazenados na construção de dashboards e painéis de monitoramento.
- **Possibilidade de compressão:** oferece recursos para reduzir o espaço ocupado por dados históricos.
- **Suporte a políticas de retenção:** permite estabelecer estratégias para gerenciamento do ciclo de vida dos dados armazenados.

### Consequências negativas

- **Complexidade de configuração:** a utilização de uma extensão especializada do PostgreSQL exige conhecimentos específicos sobre hypertables, particionamento e administração do banco.
- **Gerenciamento de armazenamento:** o crescimento contínuo das leituras exige planejamento de capacidade, retenção e políticas de compressão.
- **Dependência tecnológica:** a adoção de recursos específicos do TimescaleDB pode aumentar o esforço necessário para uma eventual migração para outro banco de dados.
- **Otimização de consultas:** consultas envolvendo grandes intervalos temporais e múltiplas máquinas podem exigir índices e estratégias específicas de otimização.
- **Consumo de recursos:** grandes volumes de inserções e consultas simultâneas podem exigir dimensionamento adequado de memória, processamento e armazenamento.

### Decisões futuras

- Definir políticas de retenção das leituras históricas.
- Avaliar a utilização de compressão para dados antigos.
- Definir índices para otimizar consultas por máquina, sensor e intervalo temporal.
- Avaliar a utilização de Continuous Aggregates para armazenar resultados de agregações temporais.
- Definir uma estratégia de backup e recuperação dos dados.
- Estabelecer mecanismos de controle de duplicidade e idempotência na persistência dos eventos provenientes do Kafka.
- Avaliar a necessidade de separar dados operacionais recentes de dados históricos.
